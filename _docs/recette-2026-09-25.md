## Défauts classifiés

### BLOQUANT

#### B1 — Bouton d'achat déclenche `prompt()` non supporté
- **Page** : `/fr/plugins/comments` (et tous plugins avec CheckoutButton)
- **Viewport** : 1440 px
- **Étapes** : 1. Ouvrir `/fr/plugins/comments` 2. Scroller jusqu'à la section tarifaire 3. Cliquer "Get Started" (plan Pro)
- **Attendu** : appel `POST /api/checkout`, redirection Stripe Checkout
- **Constaté** : erreur console `Uncaught (in promise) Error: prompt() is not supported` ; aucune requête `/api/checkout` déclenchée ; l'utilisateur ne peut pas acheter
- **Note** : déjà identifié dans le CLAUDE.md du projet : "Remplacer le `prompt()` de `CheckoutButton` par un vrai modal email (V2)" — cette V2 n'est pas encore implémentée

#### B2 — Crash 500 général après hot module replacement (HMR)
- **Pages** : toutes (testé sur `/fr`, `/fr/mentions-legales`, `/fr/veille`)
- **Viewport** : 1440 px
- **Étapes** : 1. Démarrer `npx next dev` 2. Naviguer sur plusieurs pages 3. Le HMR déclenche un Full Refresh suite à l'erreur `prompt() is not supported` 4. Toutes les pages renvoient 500
- **Attendu** : les pages continuent à se servir normalement
- **Constaté** : `Error: Cannot find module './vendor-chunks/@formatjs.js'` ; le fichier `.next/server/vendor-chunks/` ne contient que `@swc.js`, `next-intl.js`, `next.js` — `@formatjs.js` manquant. Résolution : redémarrer le serveur
- **Impact** : en dev uniquement ; à confirmer avec `npm run build` que le chunk est bien produit en production

### MAJEUR

#### M1 — Page 404 non personnalisée
- **Page** : toute URL inexistante (ex. `/fr/cette-page-nexiste-pas`)
- **Viewport** : 1440 px
- **Attendu** : page 404 aux couleurs du site, avec navigation, en français
- **Constaté** : page Next.js par défaut blanche, texte anglais "404 — This page could not be found.", aucun layout ISOMORPH

#### M2 — Lien CGV positionné sous les boutons d'achat
- **Page** : `/fr/plugins/comments`
- **Viewport** : 1440 px
- **Étapes** : 1. Ouvrir `/fr/plugins/comments` 2. Scroller jusqu'à la section tarifaire 3. Repérer le lien CGV
- **Attendu** : lien CGV visible au-dessus des boutons "Get Started"
- **Constaté** : le lien CGV est en pied de page (Y=1965 px dans le DOM) ; les boutons "Get Started" sont à Y=1336 px. Le lien est 629 px sous le bouton, non visible avant l'acte d'achat

#### M3 — Menu mobile : pas d'overlay plein écran, Escape inopérant
- **Page** : `/fr` (et tout le site)
- **Viewport** : 375 px
- **Étapes** : 1. Ouvrir le menu hamburger 2. Constater que le contenu reste visible derrière 3. Presser Escape
- **Attendu** : overlay semi-opaque couvrant tout le viewport, focus piégé, Escape ferme le menu (RGAA 4.1 critère 12.8)
- **Constaté** : le menu s'ouvre en haut (hauteur partielle), la page est visible et scrollable derrière ; Escape ne ferme pas le menu ; seul un clic précis sur le X ferme le menu

#### M4 — Carte géographique sans tuiles
- **Page** : `/fr/experimentations/carte`
- **Viewport** : 1440 px
- **Étapes** : 1. Ouvrir la page 2. Attendre 8 secondes
- **Attendu** : carte MapLibre stylisée thème Snazzy avec tuiles visibles
- **Constaté** : MapLibre GL se charge mais aucune requête de tuile n'est émise (log réseau vide). La carte affiche uniquement le cadre instrumental sur fond noir.

## Décision

**NO-GO**

Deux défauts bloquants empêchent la mise en production :

1. **B1** : le bouton d'achat ne fonctionne pas — le tunnel Stripe est cassé. Aucun revenu possible.
2. **B2** : le serveur de dev crashe après hot reload sur l'erreur `prompt()` — à confirmer sur un build de production propre.

Conditions pour passer en GO :
- B1 corrigé : `CheckoutButton` remplace `prompt()` par un modal ou une saisie inline
- B2 vérifié : `npm run build` confirme la présence de `@formatjs.js` dans le bundle
- M1 adressé : page 404 personnalisée
- M2 adressé : lien CGV visible avant les boutons d'achat
- M3 adressé : overlay mobile et Escape sur le menu
- M4 adressé : configuration de la source de tuiles MapLibre
